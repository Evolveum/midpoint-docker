= midPoint Docker

midPoint is the leading open source identity governance and administration platform (IGA).
It is a comprehensive feature-rich system that has been continuously developed and maintained by a
full-time team of professionals. midPoint is available under the terms of Apache License and European
Union Public License.

This repository holds the Dockerfiles and helper scripts for building and running midPoint container
images.

== Just run midPoint

All midPoint images are published at link:https://hub.docker.com/r/evolveum/midpoint[Docker Hub], so
you do not need to build anything to run midPoint.

Pull the image:

[source,bash]
----
docker pull evolveum/midpoint
----

For a running instance with a database in one command, use the interactive helper (it starts the
*published* image with PostgreSQL via docker compose, and can manage named instances, logs, etc.):

[source,bash]
----
./midpoint-quickstart.sh          # interactive menu
./midpoint-quickstart.sh start    # start non-interactively
----

Or bring up the stack directly with the provided compose file:

[source,bash]
----
docker compose up
----

== Build your own image

Use `build.sh` to build a current midPoint image from the Dockerfiles in `dockerfiles/`. The image is
assembled in three stages, all built locally by the script:

. *base* - OS + JDK (`dockerfiles/Dockerfile-base`)
. *dist* - the midPoint payload from the public Nexus (`dockerfiles/Dockerfile-dist`)
. *final* - the runnable image (`dockerfiles/Dockerfile`)

The distribution tarball is fetched from the public Nexus by `./download-midpoint`; no credentials are
needed.

[source,bash]
----
# latest release, alpine, non-root (midPoint 4.11+ default)
./build.sh

# a specific release on ubuntu
./build.sh --os ubuntu 4.9.1

# newest development snapshot
./build.sh devel

# midPoint 4.10 and older run as root, not the non-root midpoint user
./build.sh --runtime-user root 4.10.1
----

Common options (see `./build.sh --help` for all):

[%autowidth]
|===
| Option | Meaning | Default

| `MP_VERSION` (positional) | Release (e.g. `4.9.1`), `latest`, `devel`, or `X.Y-support` | `latest`
| `--os` | Base OS family: `alpine` \| `ubuntu` \| `rockylinux` | `alpine`
| `--os-tag` | Base OS image tag | per family
| `--java` | JDK version | `21`
| `--runtime-user` | `root` \| `midpoint` (4.11+ run as non-root `midpoint`; use `root` for 4.10 and older) | `midpoint`
| `--h2` | Enable the in-memory H2 demo repository | off
| `--base-image REF` | Reuse a prebuilt base image, skip building the base stage | -
| `--dist-image REF` | Reuse a prebuilt dist image, skip download + building the dist stage | -
| `--image` / `--tag` | Final image name / tag | `midpoint` / `<MP_VERSION>-<os>`
|===

Reusing a prebuilt stage speeds up repeated builds, e.g. build only the dist + final on top of a
published base:

[source,bash]
----
./build.sh --base-image registry.evolveum.com/public/midpoint-base:21-alpine devel
----

=== Run a locally built image

`build.sh` tags the image `midpoint:<MP_VERSION>-<os>` by default. Point the compose file at it via
`MP_IMAGE`:

[source,bash]
----
MP_IMAGE=midpoint:latest-alpine docker compose up
----

== Legacy content

The `legacy/` directory holds the previous single-stage `Dockerfile`, the Connector Server
`Dockerfile-cs`, old templates and container files. It is kept for reference only and is *scheduled
for removal in 2028*. Do not build on it.
